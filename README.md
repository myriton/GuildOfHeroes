## Практическая работа №3

### Ошибки 
1. Ошибка: public int Health { get; set; } — внешняя запись снова разрешена. 
Исправление: public int Health { get; private set; }. 
Проверка: alexander.Health = -100; перестало компилироваться, строка удалена, проект запускается
2.  Ошибка: value.Trim(); _name = value; — результат Trim() не сохранён. Исправление: _name = value.Trim();. Проверка: временный объект new Hero("   Александр   ", 150) вывел [Александр] без пробелов

### Ответы
1. **Запрет внешней записи** — это ограничение доступа. Свойство Health объявлено как public int Health { get; private set; }. Читать его может любой код, но присваивать — только код внутри класса Hero. Поэтому строка alexander.Health = -100; в Program.cs не компилируется. 
**Проверка допустимого числа** — это правило модели. Оно выполняется там, где запись разрешена: внутри Hero.
**При создании** здоровье проверяется в конструкторе Hero(string name, int health). 
**При изменении** границы сохраняют методы: TakeDamage() не опускает здоровье ниже 0, Heal()  не поднимает выше MaxHealth
2. name (параметр конструктора) - Name = name; запускает set, внутри set это же значение доступно как value, проверка IsNullOrWhiteSpace + value.Trim() - результат пишется в _name. Поэтому в конструкторе нужно Name = name;, а не _name = name; — иначе проверка обходится
3. При создании с `-100` конструктор дал `0/100`: отрицательное здоровье стало нулём, а запасной предел — 100. При создании с `5000` получилось `200/200`: и здоровье, и предел обрезались до общего потолка. Александр начинал с `150/150`, после урона 30 и лечения 10 стало `130` — в пределах. Лечение на 5000 подняло здоровье до `150`, но не выше личного предела. Отрицательное лечение −20 ничего не изменило: осталось `150`. Большой урон 5000 опустил здоровье до `0`, и `IsAlive()` вернул `False` — ниже нуля не ушло. Лечение на 20 из нуля дало `20`. Артём при всех действиях Александра остался `120/120`, то есть объекты независимы.

### ПР №3. Инкапсуляция собственного класса

Класс и его назначение:
`Movies` описывает фильм в каталоге: название, жанр, год выпуска и рейтинг. Класс хранит данные о фильме и умеет добавлять новую оценку, пересчитывая средний рейтинг

Какие данные защищены и почему:
Защищён рейтинг `Rating`: он должен всегда находиться в диапазоне 0–10, иначе значение перестаёт быть осмысленным рейтингом фильма. Также защищено имя `Name`: оно не должно быть пустым и не должно содержать лишних пробелов по краям

Какие свойства имеют private set:
`Rating` объявлен как `public double Rating { get; private set; }` — чтение открыто, запись доступна только коду внутри `Movies`. `Name` — полное свойство с `private set`: снаружи имя читается, но переименовать фильм прямой записью нельзя

Какое свойство использует закрытое поле:
`Name` использует закрытое поле `_name`

Что проверяют конструктор и методы:
Конструктор проверяет начальный рейтинг и приводит его к диапазону 0–10. Метод `AddScore` добавляет оценку и усредняет рейтинг. Недопустимая оценка вне 0–10 отклоняется ранним `return;`, а после усреднения рейтинг снова приводится к диапазону 0–10, чтобы правило соблюдалось после каждого вызова

Проверки двух объектов и полученные результаты:
```
Console.WriteLine($"Рейтинг до: {everest.Rating}");

everest.AddScore(10);
Console.WriteLine($"После допустимой оценки: {everest.Rating}");

everest.AddScore(-2); 
Console.WriteLine($"После недопустимой оценки: {everest.Rating}");

```
до действия рейтинг 7,1, `AddScore(10)` - 8,55, `AddScore(-2)` отклонён - 8,55 (недопустимое действие не нарушило диапазон)

## Практическая работа №4

1. Элемент списка хранит не сам объект целиком, а ссылку на него в памяти. Благодаря этому список может хранить объекты сложных классов
2. Потому что new Hero(...) только выделяет память и создает объект. Чтобы он попал в коллекцию, нужно явно вызвать метод Add у списка 
3. Count — это количество элементов в списке. Индексация начинается с нуля, поэтому последний индекс всегда на единицу меньше количества
4. Переменная hero — это локальная переменная цикла, которая на каждой итерации хранит ссылку на текущий объект Hero из списка. Цикл сам перебирает элементы и подставляет их по очереди
5. Потому что и переменная и элемент списка хранят ссылки на один и тот же объект в памяти. Изменяя состояние объекта через переменную, мы меняем его для всех, кто на него ссылается
6. private set запрещает полностью заменить список на другой, он разрешает изменять содержимое текущего списка

Трассировка: мой прогноз `3, 70, Первый: 70, Второй: 80, Первый: 70, Второй`, фактический вывод совпал
Ошибка 1: причина использование `Count` вместо `Count - 1`, исправление `guild.Heroes[guild.Heroes.Count - 1]`. Ошибка 2: причина `new Hero(...)` создает второй независимый объект, а не копирует ссылку, исправление `probeList.Add(probeHero)`
Самостоятельный шаг: подсчёт дал 2 (Артём и Александр), самый здоровый Александр (150); ответы на два вопроса Начальным значением берем `guild.Heroes[0]`, потому что это гарантирует, что мы сравниваем с реальным существующим объектом. Если бы здоровье было одинаковым, в `strongest` остался бы первый из них, так как в условии стоит строгое больше
